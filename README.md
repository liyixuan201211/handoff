# 交接 Handoff

**你只管说想要什么。剩下的，交给一支 AI 团队。**

---

## 它解决的是什么问题

现在所有人都说"用 AI 能提高效率"。但你去问一个护士、一个小店主、一个中学老师，
他们会告诉你：**我不知道该怎么问它。**

「帮我看看这份合同」——AI 回你一段正确的废话。
「帮我写个简历」——AI 写出来一堆你根本没干过的事。
「帮我做个学习计划」——AI 给你一张漂亮但坚持不了三天的表。

问题不在模型不够聪明。问题在于**从"我有个麻烦"到"AI 真正把它办完"中间隔着好几步**，
而这几步，普通人跨不过去。

**交接做的事情，就是把这几步接过来。**

你只负责两件事：**说清楚你想要什么**，和**验收结果**。
中间的理解、拆解、查资料、动手做、自我挑毛病、改稿、质检、打包交付——
由一支有明确分工的 AI 团队完成。而且每一步你都能看见。

---

## 它是怎么工作的

你说一句人话，比如：

> 帮我把这份租房合同看一遍，我怕有坑。押金两个月6000元，租期一年，提前退租押金不退，
> 水电燃气租客承担，维修超200元租客承担。

然后会有 8 位"同事"依次接手：

| 谁 | 岗位 | 干的事 |
|---|---|---|
| 小接 🫱 | 接待员 | 把你的话听懂，判断你真正想要什么 |
| 小方 📋 | 项目经理 | 把这件事拆成能干活的步骤，定下交付什么 |
| 小查 🔍 | 调研员 | 补齐需要的背景知识和常识 |
| 小做 ✍️ | 执行专员 | 真正把东西写出来 |
| 小挑 🔎 | 审查员 | 专门挑自己的毛病（挑得挺狠） |
| 小改 🛠️ | 执行专员 | 按挑出来的问题改一遍 |
| 小验 ✅ | 质检员 | 代表你逐条验收，该说不行就说不行 |
| 小交 📦 | 交付专员 | 告诉你拿到东西之后怎么用 |

最后你得到的是几份**能直接用**的文档，外加一份「怎么用」的说明。

**四件我们认为很重要的事：**

1. **你能看见他们在干什么。**每个阶段实时显示谁在做、做了多久、说了什么。
   不是转圈圈等 3 分钟然后蹦出一段字。

2. **我们如实告诉你"替你假设了什么"。**比如上面那个例子，我们会说
   「假定你是承租方」「假定房子在中国大陆」。
   假设错了，你一句话就能让我们重做。

3. **我们不会反问你一堆问题。**默认策略是**先做，把假设亮出来**。
   只有真的会做错方向时才问你，最多两个问题，而且是选择题。

4. **质检员会真的说不行。**它不是走过场。发现自己的产出有问题会直接写"需要重做"，
   而不是硬着头皮交给你。

## 怎么用起来

### 你需要什么

- 一台 Mac / Linux / Windows 电脑
- Node.js 22.5 以上（`node -v` 看一下）
- 一个模型服务的 API Key（**如果你装了 Cherry Studio，我们已经能自动读到，你什么都不用填**）

### 三步启动

```bash
cd handoff
npm install
npm start
```

然后打开浏览器访问 **http://127.0.0.1:8787**

就这样。没有注册、没有登录、没有云服务、没有数据上传。

### 关于 API Key

**优先级从高到低：**

1. 环境变量 `AIPING_API_KEY` 或 `DEEPSEEK_API_KEY`
2. **自动读取你本机 Cherry Studio 的配置**（零配置，装了就能用）
3. 复制 `.env.example` 成 `.env` 自己填

> 你的 Key 只在这台电脑上使用，只发给你指定的模型服务商。
> 我们不会把它写进日志、不会放进任何 HTTP 响应、不会上传到任何地方。
> 相关代码在 `src/llm/providers.js`，你可以自己看。

### 想先看看效果，不想花 API 的钱？

```bash
HANDOFF_DEMO=1 npm start
```

演示模式下不调用任何模型，用内置的示例数据把完整流程跑一遍。
网络断了、没 Key 也能用。

## 常用配置

在项目根目录建一个 `.env`（照 `.env.example` 抄）：

| 变量 | 默认值 | 说明 |
|---|---|---|
| `HANDOFF_PORT` | `8787` | 端口 |
| `HANDOFF_HOST` | `127.0.0.1` | 监听地址。**默认只允许本机访问**，不要随便改成 `0.0.0.0` |
| `AIPING_API_KEY` | 自动读取 | AI Ping 的 Key（提供 DeepSeek 等模型） |
| `DEEPSEEK_API_KEY` | 自动读取 | DeepSeek 官方 Key |
| `HANDOFF_MODEL_CHAIN` | 见下 | 模型降级链，逗号分隔，从左到右尝试 |
| `HANDOFF_DATA_DIR` | `./data` | 任务数据存放目录 |
| `HANDOFF_DEMO` | `0` | 设为 `1` 进入离线演示模式 |
| `HANDOFF_LLM_TIMEOUT_MS` | `120000` | 单次模型调用超时 |

默认的模型降级链：

```
deepseek-flash → aiping/DeepSeek-V4-Flash → aiping/DeepSeek-V4.1-Flash → aiping/GLM-5.3 → aiping/Qwen3.8-Max
```

**为什么要有一整条链？**因为普通人不会重试。主模型超时或限流时，
系统会自动换下一个继续，你不会看到失败。界面上会提示"已自动切换到备用模型"。

## 它不会做什么（诚实说明）

- **不会替你做决定。**它给你分析和建议，签不签字、去不去谈，是你的事。
- **不是医生，不是律师。**涉及健康和法律的场景，它帮你**听懂、少走弯路、准备好该问的问题**，
  但最终要听专业人士的。
- **不保证内容都对。**模型会犯错。所以每一个交付物都带质检结论，
  而且质检员被明确要求"发现没做到就写 false，不要放水"。
- **不是军事级安全。**它比大多数同类产品认真（见 `docs/SECURITY.md`），
  但别用它处理你不愿意承担任何风险的东西。

## 开发

```bash
npm test                    # 全部测试
npm run test:unit           # 单元测试
npm run test:e2e            # 端到端（含离线演示模式）
node scripts/dry-run.js     # 真跑一次完整流水线（需要网络 + Key）
```

`scripts/dry-run.js` 会真的调用模型、真的跑完 8 个阶段、打印每一份交付物的开头，
最后按 `docs/CONTRACT.md` §7 的验收标准逐条打勾。想确认"它到底能不能干活"就跑这个。

## 技术选择

- **Node.js + Express，零框架前端。**没有构建步骤，`git clone` 完就能跑。
  对一个人维护的项目来说，少一层构建就少一类故障。
- **只用 3 个依赖**（express / vitest / supertest）。安全面越小越好，
  也便于你审计我们到底干了什么。
- **数据存本地 JSON 文件。**原子写入，重启不丢，你随时能打开看。
  没有数据库要装，也没有云要连。
- **不调任何第三方接口**，除了你指定的模型服务商。
  没有统计、没有埋点、没有 CDN。断网也能打开界面。

「交接」——把你手里那件不知道该怎么交给 AI 的事，交出去。

我们希望你用完之后的感受是：
**"我把事说出去了，它办完了，而且我知道它怎么办的。"**
