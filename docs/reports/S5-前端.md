## 我发现的真实缺陷（真机复现，非"看起来对"）

这三个都是**只有真正在浏览器里跑起来才会暴露**的问题，Node 单测和语法检查全绿也照样存在。
按负责人要求，附上复现方式。

### 缺陷 1：store 订阅者的路由守卫会永久挡掉后续变更 → 历史页永远停在骨架屏

**现象**：`#/history` 打开后，接口已经返回 3 个任务，但页面永远显示骨架屏；手动调 `render()` 立刻正常。

**根因**：`start()` 里的订阅者第一行是

```js
if (routeKey !== lastRouteKey) return;   // ← 这一行
```

`lastRouteKey` **只在 `jobsKey` 变化的分支里**被赋值。所以首次进入时 `routeKey('history') !== ''`
直接 return 且 `lastRouteKey` 永远是 `''`，之后**每一次** jobs 变更都再次命中这个 return，
`if (state.route.name === 'history') render();` 永远执行不到。

**复现**：

```bash
node -e "/* 起一个返回 3 条任务的 mock（见下）*/"
# 浏览器打开 http://127.0.0.1:PORT/index.html?x=1#/history
# 观察：接口 200 且返回 3 条，页面仍是 .skeleton
```

真机证据（修复前）：
```
state: {"jobs":"ready","n":3,"route":"history"}   ← 数据早就到了
domCards: 0, domSkeleton: 1                       ← 但 DOM 还是骨架屏
```
手动执行 `render()` 后立刻 `afterCards: 3, skeleton: 0` —— 证明是"没人触发重渲染"，不是数据问题。

**修法**：守卫改成"记录并返回"，不再影响下一次判断（`public/app.js` 的 store.subscribe）。

### 缺陷 2：SSE 的 `job` 快照没校验任务身份 → 整页被别的任务顶掉（串任务）

**现象**：URL 明明是 `#/job/job_bad01`，页面却完整渲染成 `job_demo01` 的目标、阶段和交付物。
**只有真机能发现**：单测里 store 和 API 各自都对，是"事件流的身份"错了。

**根因**：`evt.type === 'job'` 时无条件合并快照。重连/服务端补发时，如果推来的是别的任务
（我的 mock 一度把 demo 任务快照推给了 `job_bad01` 的流），整页就被替换掉了。

**复现**：起一个 mock，让 `/api/jobs/A/stream` 的第一条 `{"type":"job"}` 里放任务 B 的快照，
打开 `#/job/A` → 看到的是 B 的内容。

真机证据（修复前，靠临时给 `patchHead` 打日志抓到）：
```
"snapshot job_bad01 -> job_bad01/把这份 20"   ← GET 拿对了
"patchHead job=job_bad01/把这份 20"
"patchHead job=job_bad01/把这份 20"
"patchHead job=job_demo01/帮我把这份租"        ← 被 SSE 快照顶掉
```
**修法**：① `incoming.id !== this.jobId` 时丢弃快照并回退 `refreshSnapshot()` 用权威数据纠正；
② 给 `JobView` 加 `isOwner()`（`!this.destroyed && currentView === this`），
已被换掉的视图只允许更新 store、**绝不允许再碰 DOM`（防止"迟到的快照"画到新页面上）。

### 缺陷 3：SSE 元信息快照会冲掉已经拿到的交付物正文

**现象**：详情接口已经返回了 `artifacts[].content`，首屏交付物却显示成"成果已经写好了（196 字），
点一下展开看正文"——正文被后来的 SSE 快照抹掉了。

**根因**：契约规定 SSE 的 `job` 快照里 `artifacts[]` **只有元信息、不含 content**。
`mergeJob()` 原来用 `Object.assign(local, incoming)` 整体覆盖，把 `content` 一起冲掉了。
这是典型的**事件顺序 bug**：`GET` 先回、SSE 后到，后到的"更少信息"覆盖了"更多信息"。

**修法**：合并时按 `id` 匹配，`incoming` 没有 `content` 而本地有时**保留本地正文**。
（状态/日志同理由此前的合并逻辑保护。）

真机证据（修复前/后对比）：
```
修复前: {"mdH1":null,"pendingBtn":1,...}                    ← 正文被冲掉
修复后: {"mdH1":"出租屋安全隐患自查表","mdStrong":"4 个区域",
        "mdBlockquote":true,"mdPre":"每月检查一次并签字。",
        "mdLink":"https://example.com/safety","pendingBtns":0}   ← 直接渲染
```

2. **占位符用 NUL 被自己吃掉（3 个失败）**——占位符最初用 `\u0000<n>\u0000`，

   并在渲染前把输入里的 `\uE000` 一并删掉，保证用户无法伪造占位符。
3. **`#/job`（无 id）和未知路由（2 个失败）**——原本 `#/job` 会被当成详情页去请求
   `/api/jobs/undefined`，`#/whatever` 被静默当成首页。改成分别回首页 / 显示"页面不存在"。

## 关键实现说明（安全工程师重点看这里）

### markdown 渲染器的流程（不可颠倒）

1. `stripControlChars` 剥控制字符，并**删掉 U+E000 哨兵**（用户无法伪造占位符）
2. ``` 围栏代码块**从原文取出** → `escapeHtml` → `<pre><code>`，原位留占位符
3. `` `行内代码` `` 同样从原文取出 → `escapeHtml` → `<code>`
4. 其余每一段文本**先 `escapeHtml`，再包标签**（粗体/链接/斜体）
5. 最后把占位符换回**已构建好的安全 HTML**

> 踩坑记录：第一版先把整行 `escapeHtml` 再找反引号，结果 `escapeHtml` 把 `` ` `` 变成 `&#96;`，
> 代码块再也认不出来（测试立刻抓到了）。所以代码必须先摘、后转义。
> 另：第一版占位符用了 NUL `\u0000`，被 `stripControlChars` 自己吃掉了 → 改用私用区 `\uE000`。

### XSS 防线

- `escapeHtml` 转义 `& < > " ' ` ` 六个字符
- **禁止用 innerHTML 插入未转义内容**：`el()`/`setText()` 一律走 `textContent` + `createElement`；
  唯一的 `innerHTML` 赋值点是 `setRenderedMarkdown()`，只接受 `renderMarkdown()` 的输出
- 链接白名单：只允许 `http://` `https://` `mailto:`；其余（含 `javascript:` `data:` `vbscript:`
  `file:` `blob:` 及 `java\nscript:` 这类控制字符伪装）**退化成纯文本**；合法链接强制
  `target="_blank" rel="noopener noreferrer nofollow"`，且 href 二次 `escapeHtml`
- 测试里有 **8 条攻击载荷 × 8 种包裹方式**（正文/标题/列表/引用/粗体/行内代码/代码块/链接）
  的**标签白名单**断言：只允许 `p br h1-h6 ul ol li blockquote hr pre code strong em a` 这 18 个标签，
  多一个都算失败

## 我做的交互设计决策清单

1. **首页就是新建任务**——大输入框直接提交，不让用户先点「新建」再填。`Enter` 直接提交，`Shift+Enter` 换行（`isComposing` 保护中文输入法）。
2. **先快照后 SSE**——进详情页先 `GET /api/jobs/:id` 拿全量渲染，再接 `EventSource`。顺序反了会先闪一个空团队，所以我把顺序写死在 `mount()` 里。
3. **SSE 只做局部 patch**——阶段卡按 `stageId` 缓存 DOM 引用，`stage` 事件只改状态徽章和耗时文本；日志用 100ms 节流 + `requestAnimationFrame` 合并批量追加。**用户展开的日志永远不被收起**（真机验证过）。
4. **耗时实时走秒**——进行中的阶段每 250ms 只改一个 `textContent`；没有进行中的阶段降到每 10 秒一次，省电。数字用等宽字体 + `tabular-nums`，走秒时不抖动。
5. **日志收起的阶段不写 DOM**——没展开就不插入节点（超过 40 条时），展开时一次性补齐，避免高频日志把布局拖垮。
6. **四块结果做成 tab**——交付物 / 验收 / 安全检查 / 我们替你做的假设。tab 带数量徽章，支持 `←/→/Home/End` 键盘切换。
7. **失败文案绝不甩报错**——固定三段：哪一步（阶段名 + 角色名）、为什么（人话翻译）、你按一下就接着做。并明确承诺「之前做的都留着，不用重头再来」。
8. **重试期间保留占位**——点重试后显示「正在让团队接着做，稍等…」，等状态真正变了再重建面板，不让面板出现空白瞬间。
9. **不整页重渲染**——`patchHead` / `patchDetail` / `patchActions` 都带幂等 key，状态没变就不重建 DOM；这也修掉了「重复调用把面板清空」的隐患。
10. **交付物正文按需取 + 缓存**——因为详情接口不返回 `content`，先显示「成果已经写好了（N 字）」按钮，点击后从下载端点取一次缓存；复制/下载都复用缓存，不再重复请求。
11. **状态色一套走到底**——等待灰、工作中蓝（脉冲点）、完成绿、失败红，深色浅色都调过对比度；同时尊重 `prefers-reduced-motion` 关掉脉冲和骨架屏动画。
12. **断网不让页面变白**——横幅提示 + 「重连」按钮，已渲染的团队和交付物**原地保留**。
13. **空状态一定有出口**——历史为空给「现在就说一件想做的事」按钮；模板接口挂了用 6 个内置模板兜底并解释一句「不影响使用」；未知路由给「回首页」。
14. **可访问性**——语义标签（`header/nav/main/section/ol/li/article/time`）、实时区 `aria-live="polite"`（连接态、阶段列表、回答框状态）、阶段卡按钮 `aria-expanded`、`sr-only` 补状态文字、`:focus-visible` 焦点环、跳到主内容链接。
15. **移动端**——390/400px 断点收窄间距、隐藏品牌副标题与顶栏 CTA（导航里仍有「新建任务」入口），360px 实测无横向滚动。
16. **诚实性做成显眼样式**——「我们替你做的假设」用虚线琥珀色卡片，并在正文顶部说明「哪条猜错了直接说，我们重做」。
