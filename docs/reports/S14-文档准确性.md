### 2.1 最重要的发现：`.env` 文件完全不被读取（⚠️ 验证期间已被同事部分修复）

README 第 111 行：「在项目根目录建一个 `.env`（照 `.env.example` 抄）」。
`.env.example` 第 1 行的承诺：「本产品**默认零配置**……只有在你没装 Cherry Studio、或者想用自己的 Key 时，才需要下面这些。」

**第一次实测（03:12，发现时）—— 静态证据：**

```
$ grep -rn "dotenv\|loadEnvFile\|\.env" src/ scripts/
src/runtime-flags.js:12:  (只匹配到 process.env 用法)
src/llm/gateway.js:111:   (只匹配到错误提示文字「可以在项目根目录的 .env 里填」)
... 无一处读取 .env 文件
```

当时 `package.json` 的依赖里没有 `dotenv`，`npm start` 脚本是裸的 `node src/server.js`，**没有 `--env-file`**。

**第一次实测 —— 动态证据（真的建一个 `.env`）：**

```
$ printf 'HANDOFF_PORT=9911\nHANDOFF_DATA_DIR=./data\n' > /tmp/hf-envtest/.env
$ cd /tmp/hf-envtest && HANDOFF_DEMO=1 node src/server.js
[server] 交接 Handoff 已启动：http://127.0.0.1:8787  (dataDir=/private/tmp/handoff-envtest/data)

$ curl -s -m 2 http://127.0.0.1:9911/api/health
⚠️ CONNECTION REFUSED on 9911
```

配置写的是 9911，服务跑在 8787。`.env` 被完整忽略。

**第二次实测（03:26，同事已修）**：`package.json` 的 `start`/`dev` 已改成
`node --env-file-if-exists=.env src/server.js`，**通过 `npm start` 启动时 `.env` 生效**：

```
$ npm start
> node --env-file-if-exists=.env src/server.js
[server] 交接 Handoff 已启动：http://127.0.0.1:19911  (dataDir=/tmp/hf-env3/dotdata)
$ curl -s http://127.0.0.1:19911/api/health
OK dataDir= /tmp/hf-env3/dotdata demoMode= True
```

**但残留一个缺口**：直接 `node src/server.js`（不走 npm 脚本）时 `.env` 仍然无效：

```
$ cd /tmp/hf-envtest && node src/server.js
[server] 交接 Handoff 已启动：http://127.0.0.1:8787   # ← 仍忽略 .env
```

这影响到 README L166 的 `node scripts/dry-run.js`、`scripts/smoke.js`，
以及 Docker / systemd / PM2 等不经过 npm 脚本的部署方式。
**完整分析与两种修法见 §6 错误 #1。**

  function loadDotEnvFile() {

    if (typeof process.loadEnvFile !== 'function') return;

  }
