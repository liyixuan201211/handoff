## A-0. 四个致命缺陷（在真实浏览器里复现）

> **前三个是"路不通"，第四个是"路上的补给没送到"。** 四个都指向同一件事：**这个产品里写好的好东西，没有到达用户手上。**

### 缺陷 1：所有任务接口的返回被包了一层 `{job:{...}}`，前端按扁平对象读

**接口实际返回**（我直接 curl 验证）：

```
$ curl -s -X POST localhost:8899/api/jobs -d '{"goal":"..."}'
{"job":{"id":"job_4150840f1649443a", ...}}     # HTTP 201

$ curl -s localhost:8899/api/jobs/job_4150840f1649443a
{"job":{"id":"job_4150840f1649443a","status":"done", ...}}   # HTTP 200
```

服务端写得很清楚 —— `src/routes/jobs.js:291` / `:312` / `:331` / `:343` 全部是 `res.json({ job: ... })` / `res.status(201).json({ job: ... })`。

**前端却按扁平对象读**：

| 前端代码 | 代码 | 实际读到 | 结果 |
|---|---|---|---|
| 提交任务 | `public/app.js:185-190`<br>`const job = await api.createJob(...)`<br>`if (job && job.id) {...}` | `job = {job:{...}}`，`job.id` = `undefined` | 走 else 分支，报错 **`任务创建了但没拿到编号，去历史里看看。`** |
| 打开任务 | `public/app.js:590-592`<br>`const job = await api.getJob(this.jobId)`<br>`if (!job \|\| (job.id && job.id !== this.jobId)) return;` | `job.id` = `undefined` → 判断为 falsy，**侥幸没 return**；但下一行 `store.set({ job })` 存进去的是**包装壳** | 整个详情页渲染壳子 |
| 发澄清回答 | `public/app.js:1252` `await api.sendMessage(job.id, value)` | `job` 是壳，`job.id` = `undefined` | 请求打到 `/api/jobs/undefined/message` |
| 重试 | `public/app.js:1308` `await api.retryJob(job.id)` | 同上，`undefined` | 请求打到 `/api/jobs/undefined/retry` |

**我在浏览器里实测到的原文**：

```
# 李姐填好"帮我看这份租房合同有没有坑，我怕押金要不回来"，点「开始，交给团队」
URL: http://127.0.0.1:8899/#/new
composer-error: {"hidden":false,"text":"任务创建了但没拿到编号，去历史里看看。"}

# 张姨点开历史里那个"已完成"的任务
（没有写下目标）
未知状态
你的团队
团队正在集结，马上就会出现在这里。
交付物
成果正在写，写完会出现在这里。
```

**这个 bug 最恶毒的地方**：两句话都在**说谎**。
- `任务创建了但没拿到编号` —— 任务**真的创建了**（我打开 `/api/jobs` 能看到它已经 `done`，8 个阶段全跑完，3 份交付物）。用户被告知"去历史里看看"，去了，看得到；但点进去只有一句"没有写下目标"。
- `成果正在写，写完会出现在这里。` —— 根本没在写。这个任务早就做完了。**用户会一直等下去**，等到关掉页面。李姐的原话会是：「它是不是卡住了？」

**为什么测试全绿**：
- `tests/unit/frontend.test.js:420` 测的是 `api.createJob()` 返回什么（`api` 层返回原始 body，没写错）。
- `tests/e2e/pipeline.test.js` 全程用 `request(app).post('/api/jobs')` **直接打服务端**（`tests/e2e/pipeline.test.js:59`、`:105`、`:112`、`:283`），从不经过 `public/app.js`。
- 于是「api 层有测试」+「服务端有 e2e」= 两段都绿，**中间那根线没人测**。

**修复方向**（给负责人）：在 `api.js` 的 `createJob` / `getJob` / `sendMessage` / `retryJob` 里统一解包，或统一在 `app.js` 调用处解包。**改一处，四处都好**。建议在 `api.js` 层解包，因为 4 个调用点分散在 `app.js`，一处漏掉就是下一个 bug。

> 建议的修法（我没有动源码，只给建议）：
> ```js
> // public/api.js  —— createJob / getJob 等所有返回 {job} 的接口统一解包
> const unwrapJob = (body) => (body && body.job && typeof body.job === 'object' ? body.job : body);
> ```
> 四个调用点改为 `await api.createJob(...)` 内部已解包，`app.js` 一行都不用改。
> **注意** `listJobs` 返回的是 `{jobs:[...]}`，`app.js:1378` 已经正确地解了，别把这条也改坏。

### 缺陷 2：演示按钮在空输入框上直接失败，而它恰好是新用户第一个会点的按钮

`public/app.js:247-255`：

```js
const run = (demoMode) => submitNewJob(ta.value, {
  audience: audience.value,
  tone: tone.value,
  templateId: o.templateId || undefined,
  demo: demoMode === true,
}, ui);

submit.addEventListener('click', () => run(false));
demo.addEventListener('click', () => run(true));      // ← 按钮文案是"看一个演示（不花钱）"
```

`submitNewJob` 第一件事是校验输入（`public/app.js:172-177`）：

```js
const clean = String(goal || '').trim();
if (!clean) {
  ui.showError('先写一句话，说明你想要什么。');
  ui.focus();
  return;
}
```

**实测**（干净会话、空输入框、点「看一个演示（不花钱）」）：

```
=== AFTER DEMO CLICK ===
...
先写一句话，说明你想要什么。
```

**这就是李姐的死亡路径**：她不会写、不知道说什么（这是她自己承认的最大障碍），于是**去看演示**——这是页面上唯一一个「不用我想、我先看看」的按钮。结果她得到的是一句责备：`先写一句话，说明你想要什么。`
**李姐的解读**：「哦，得先写啊……可是我就是不知道写什么才点的演示。」→ 关掉。**一次失败就不再用**，这次是第一次。

顺带一提：这个按钮的**位置**在输入框右下角，紧挨「开始，交给团队」，视觉上像是「我不想打字，直接带我走」。它的实现却是「拿你输入框里的话去跑演示」。

### 缺陷 4：场景模板点下去只填了一个**标题**，模板里精心写的所有内容全部没进界面

**这是我在走查中最心疼的一条 —— 因为 `templates/*.json` 写得非常用心，但用户一个字都看不到。**

#### 界面承诺 vs 实际行为

界面上的承诺（`public/app.js:305`）：

> `点一下就会填进上面的框里，你还可以改成自己的说法。`

**我实测**（点「帮我看懂检查报告 / 看病前准备」这张卡）：

```
TEXTAREA VALUE AFTER CLICKING TEMPLATE:
"帮我看懂检查报告 / 看病前准备"          ← 就这一行标题
```

**输入框里被填进去的是模板的标题**，不是一句可以拿去用的话。这一行代码就是全部原因（`public/app.js:313-314`）：

```js
grid.appendChild(templateCard(tpl, (picked) => {
  textarea.value = picked.goal || picked.title || '';   // ← picked.goal 不存在 → 退化成 picked.title
```

服务端返回的模板对象里**没有 `goal` 字段**（字段名是 `goalTemplate`），所以永远走 `picked.title`。

#### 模板文件里到底有什么（都没显示）

我打开 `templates/health-prep.json`，它长这样：

```json
{
  "id": "health-prep",
  "title": "帮我看懂检查报告 / 看病前准备",
  "emoji": "🩺",
  "category": "身体健康",
  "description": "把看不懂的指标翻译成人话，并帮你整理好该问医生的问题。",
  "placeholders": [
    { "key": "report", "label": "报告上的内容", "example": "总胆固醇 6.8，低密度脂蛋白 4.2，其他正常" },
    { "key": "situation", "label": "你的情况", "example": "52岁，平时不太运动，偶尔头晕" }
  ],
  "goalTemplate": "帮我看懂这份检查报告，用大白话告诉我哪些指标不正常、可能意味着什么。报告内容：{{report}}。我的情况：{{situation}}。另外帮我列一份下次看医生时该问的问题清单。",
  "tips": "⚠️ 我们不是医生，不能诊断。这份东西是帮你听懂医生说啥、少走弯路，最终一定要听医生的。",
  "notice": "本模板不提供医疗诊断，仅帮助理解报告与准备问诊问题。"
}
```

**`placeholders`（2 个带标签和示例的输入引导）、`goalTemplate`（一整段写好的话）、`tips`（那句写得极好的免责说明）、`notice` —— 四样东西，用户一样都看不到。**

我逐项 grep 确认前端**完全没有读取**这些字段：

```
$ grep -c "goalTemplate" public/app.js   → 0
$ grep -c "tips"         public/app.js   → 0
$ grep -c "notice"       public/app.js   → 0
$ grep -c "placeholders" public/app.js   → 0
```

服务端也确实没用（`grep -rn "goalTemplate" src/` → 零命中）：
- `src/pipeline/engine.js:121-141` 的 `loadTemplate()` 读到模板后，只把它当**校验用**，产物是 `templateId: template?.id ?? null`（`:141`）—— 即"这个任务用了哪个模板"的一个标记。
- **所以 `goalTemplate` 从来没有人做变量替换，`placeholders` 也从来没有变成表单字段。**

#### 我在浏览器里逐项验证的结果

```
DOES PAGE SHOW GOAL TEMPLATE / TIPS / NOTICE?
  ABSENT: 我要向              ← 投诉模板写好的句子
  ABSENT: 把合同内容粘贴       ← 合同模板的 goalTemplate 正文
  ABSENT: 我们不是医生         ← ★ health-prep 的 tips，全项目最好的一句免责说明
  ABSENT: 总胆固醇            ← placeholder 示例
  ABSENT: 报告上的内容         ← placeholder 标签
  ABSENT: 你的情况            ← placeholder 标签
```

**「我们不是医生，不能诊断……最终一定要听医生的。」这句话，张姨永远看不到。**
而它恰恰是这个产品里**最该被看到的一句话** —— 因为它保护的是用户的健康决策，也保护产品自己。

#### 这个缺陷对四类用户的含义

- **张姨**（62，看检查报告看不懂、不敢多问医生）：她点「帮我看懂检查报告」，**这是她最需要帮助的时刻**。结果输入框里只有一行标题，她还是不知道该写什么。**帮助就在文件里，但没送到她手上。**
- **李姐**（不敢多问医生 → 同张姨）：同上。
- **老王**（被房东涨租、供货商坑过）：他点「帮我写投诉/维权的话」，输入框填的是「帮我写投诉/维权的话」——**他要自己从头想说辞**。模板里写好的那段"有理有据、不卑不亢"的句式，他看不到。
- **小陈**：他会自己重写，所以受害最小。**恰好是唯一不需要模板的人不受影响。**

#### 修复方向

**这条不该只当成 bug 修，而应该当成一个产品机会。** 模板文件已经把该做的都写好了，只差"送到界面上"：

1. **最小修复**：点卡片时填 `goalTemplate` 而不是 `title`，并把 `{{xxx}}` 占位符替换成 `placeholders[].example`（这样输入框里出来的就是一段能直接用的、带真实示例的话）。
2. **更好的做法**：点卡片后，把 `placeholders` 渲染成 2-4 个小输入框（标签 + 灰色示例），用户填完自动拼成 `goalTemplate`。**这才是"不愿填表"用户的福音 —— 因为每个框里都有现成示例，他照着改就行，不用从零想。**
3. **必做**：`tips` 和 `notice` 必须显示出来，尤其是 `health-prep` 和 `contract-review` 这两个涉及健康与法律的。至少显示在输入框下方。

| **我不知道说什么，有救吗？** | ❌ **不能** —— **救命的那一屏在首屏之外**（第 6 层场景模板需要滚动）。李姐卡在空输入框时，她**看不到**「不知道怎么说？挑一个常见场景」这一屏。她会停在原地 | `public/app.js:303-305` |
| **点「看一个演示」行不行？** | ❌ **不能** —— 缺陷 2，空框直接报错 | §A-0 缺陷 2 |

### 三秒测试结论

**"这是干什么的"和"点哪里"通过了，但"说不出来怎么办"没通过——而后者恰好是李姐最大的障碍。**

**核心矛盾**：首页的**结构顺序**是「先要求你说 → 再告诉你说不出来怎么办」。对李姐这种"最容易在我该说什么这一步放弃"的用户，**顺序反了**。她会在空输入框前停住，**根本不会往下滚**，于是永远看不到那 8 个救命的场景卡片。

**建议（小改动，收益极大）**：把「不知道怎么说？挑一个常见场景」这一屏**移到输入框上面**，或至少在输入框**正下方**放 3 个最贴近生活的场景快捷入口（而不是藏在滚动之后）。参考改动：

```
【现在】 标题 → 副标题 → 输入框 → 按钮 → 流程 → 场景模板（要滚动）
【建议】 标题 → 副标题 → 场景模板（前 4 个，横排）→ 输入框 → 按钮 → 流程
```

## D. 「空白输入框」问题

### D-1. 他知不知道该说什么？

**部分知道，但全靠"猜"和"滚"。**

- **首页**：输入框有灰字提示 `比如：帮我把这份租房合同看一遍，我怕有坑`（`public/app.js:292`）。这**一个例子是有效的**，张姨看了会说"哦，原来这么说话"。但李姐的职业不是租房，她未必能**迁移**到"帮我看懂这个化验单"。
- **「新建任务」页（`#/new`）—— 这里是重灾区**：`public/app.js:341-352`

```js
function renderNew(main) {
  const page = el('div', { class: 'page page-new' });
  page.appendChild(el('section', { class: 'hero hero-compact' }, [
    text('h1', 'hero-title', '新开一个任务'),
    text('p', 'hero-sub', '一句话就够。说不清楚也没关系，接待员会先帮你把意思理清楚。'),
  ]));
  const { form } = newTaskForm({ id: 'new-goal' });   // ← 没传 placeholder
  ...
}
```

`newTaskForm` 的 placeholder 兜底是 `public/app.js:203` 的 `'比如：帮我把这份租房合同看一遍，我怕有坑'`，所以**新建页还有那个例子**。

**但新建页 `#/new` 上「场景模板」整块是缺失的。** 对比首页 `renderHome` 有 `tplSection`（`public/app.js:303-325`），`renderNew` **没有**。
**后果**：任何从顶栏点「新建任务」（`public/app.js:132`，这是**全局最容易点到**的入口）进来的用户，**落在了一个没有任何场景提示的页面上**。他只有一行灰字提示，和一句"说不清楚也没关系"。

**老王会怎么想**：他点顶栏「新建任务」→ 一个空框 → 灰字提示在说租房合同（他没房子租）→ 他想了想，关掉，去刷短视频了。

> **建议（小改动）**：把首页的 `tplSection` 抽成一个函数，`renderNew` 里也调一次。或者至少在 `#/new` 页放 4 个最生活化的场景快捷按钮。

**还有更根本的一层：他就算点了场景卡片，也还是不知道该说什么。**（详见 §A-0 缺陷 4）

界面承诺「点一下就填进上面的框里」，但实测填进去的是**标题**：

```
点「帮我看懂检查报告 / 看病前准备」后，输入框的值 = "帮我看懂检查报告 / 看病前准备"
```

**这等于把问题原样还给了用户。** 张姨点了"帮我看懂检查报告"这个**明显是给她的**按钮，输入框里还是一个"标题"，她仍然要自己组织语言。

而模板文件里**本来写着一段完整的话**（`templates/health-prep.json` 的 `goalTemplate`）：

> `帮我看懂这份检查报告，用大白话告诉我哪些指标不正常、可能意味着什么。报告内容：{{report}}。我的情况：{{situation}}。另外帮我列一份下次看医生时该问的问题清单。`

配合两个带示例的填空（`报告上的内容` → 示例"总胆固醇 6.8，低密度脂蛋白 4.2，其他正常"；`你的情况` → 示例"52岁，平时不太运动，偶尔头晕"），张姨**照着改两个数字**就能用。

**这才是解决"空白输入框"问题的正解 —— 不是写更长的说明，是把示例直接放进框里让人照着改。**

## E. 失败路径审计（最重要）

**总纲**：这个项目的失败界面**设计得好，文案也写得用心** —— `failureState` 有 `title` / `where` / `why` / `next` 四段式，还有「重试」和「重新开一个」两个出口（`public/app.js:394-401`、`:1285-1292`、`:1315-1322`）。
**但有两个系统性问题让它全部作废**：
1. **缺陷 1 让详情页永远进不到失败分支**（`job.status` 读到的是 `undefined`，不是 `'failed'`），所以这些精心写的失败界面**用户根本看不到**。
2. **`why:` 字段渲染的是服务端原始 message**（`public/app.js:1288`），而服务端的 message 是写给人看的**开发期报错**，满是 `API Key` / `.env` / 变量名。

### E-10. 额外发现：安全检查的 4 类发现里有 3 类会退化成一句含糊的兜底文案

**这是我做全量文案清点时发现的**（不改代码，只做交叉比对）：

前端为安全检查的"发现类型"准备了一张翻译表（`public/app.js:1168-1173`）：

```js
const KIND_TEXT = {
  prompt_injection: '有人可能想借你的话指挥模型（通常只是你转述了别人的文字，不用紧张）',
  pii:              '内容里出现了手机号、身份证号这类个人信息',
  unsafe_request:   '这件事我们不能照做',
  secret_leak:      '疑似密钥出现在内容里，已经打码处理',
};
```

**但服务端实际产出的类型有 6 种**（`src/security/guard.js:129-153`）：`prompt_injection`、`oversized`、`pii`、`secret_leak`、`unsafe_output`、`malformed`。

**对不上的地方**：
- `unsafe_request` 在前端有翻译，但**全仓库没有任何地方生产它**（只在 `public/app.js:1171` 出现这一次）—— 是条死文案。
- 服务端真实会产出的 `oversized`（内容太长只处理了前面一段）、`unsafe_output`（产物里有能直接粘贴运行的命令）、`malformed`（内容不完整）**在前端没有对应翻译**，于是全部落到兜底（`public/app.js:1177`）：

```js
KIND_TEXT[...] || '需要留意的地方'
```

**用户会看到什么**：张姨那份检查报告如果触发的是"内容太长只处理了前面一段"，她在「安全检查」页签里看到的是一句 **`需要留意的地方`** —— 没告诉她留意什么。

**为什么这条对普通用户要紧**：这个页签叫「安全检查」，是**建立信任的地方**。一句"需要留意的地方"会让人要么忽略它，要么莫名紧张 —— 两种结果都不好。而正确的做法很简单：**服务端已经写了很清楚的说明**（例如 `src/security/guard.js:136` 的 `内容偏长，我们只处理了前面一段。`），前端只是没用上。

**修复方向**：`KIND_TEXT` 的键以 `src/security/guard.js:129-153` 的实际产出为准对齐；更好的做法是**直接渲染服务端下发的 `detail` 文案**，而不是前端再维护一张可能过期的映射表。

**工作量：小。**

## G. 如果我们只能改 3 件事，改哪 3 件

**必须说明：下面 3 件是按"用户能不能用上"排的，不是按"哪个 bug 更严重"排的。**

### 第 1 件：修掉 `{job:{...}}` 解包问题（对应 §A-0 缺陷 1）

**理由**：不修这个，**其他所有改进用户都看不到**。
- 改文案 → 用户到不了显示文案的页面。
- 加场景模板 → 用户填完了点不动。
- 改失败提示 → 失败界面永远不渲染。
- 现在浏览器里从「开始」到「看到结果」这条路**是断的**，中间一格都不通。

**为什么它是第 1 件而不是"顺便一起改"**：因为它**同时**制造了两个错误的用户认知 ——
「任务创建了但**没**拿到编号」（其实创建了）和「成果**正在写**」（其实早就写完了）。
第二句会让李姐**一直等下去**。这不是文案问题，是**让用户在一个永远不会变化的页面上浪费时间**。

**为什么之前没人发现**：单测测 `api.js`（绿）、e2e 测服务端（绿）、报告写"四个视图全部实现"（真写了）。**缺的是一次真人点按钮。** 修完请把「浏览器真点一次完整流程」加进回归测试。

**工作量：小**（`public/api.js` 加一个 `unwrapJob` + 4 处调用）。

---

### 第 2 件：让「看一个演示」在空输入框上也能用，并且演示内容和演示目标一致（对应 §A-0 缺陷 2 + §E-9）

**理由**：这是**唯一一个能救回"不知道该说什么"的用户的按钮**，而我们的四类用户里**三类明确卡在这一步**（任务书原话：「最容易在"我该说什么"这一步放弃」）。

现在的情况是：李姐不知道说什么 → 她看到「看一个演示（不花钱）」→ 点 → 被要求先写一句话。
**她的第一次尝试就是失败。** 而任务书明确写了：「一次失败就不再用」。

而且即使她写了，演示还会给她一份和问题无关的合同报告（§E-9），**第二次打击**。

**改成**：点演示 = 直接跑一个内置案例 + 页面上明确写「演示里用的是这个例子：帮我把这份租房合同看一遍，我怕有坑」。
用户看完就知道「哦，原来我可以这样说」。**这才是演示该干的事：教会用户怎么开口。**
成本比第 1 件还低，但**对转化率的影响可能更大**。

**工作量：小**。

---

### 第 3 件：把模板里已经写好的东西送到用户手上 + 把开发期报错挡在界面外（§A-0 缺陷 4 + §B #1#2#3）

**表面上这是两件事，实际上是一件：「产品里写好的好东西，没送到用户手上」。**

一半是**好东西送不过去**：`templates/*.json` 里的 `goalTemplate`、`placeholders`、`tips`、`notice` 全都写得很用心（`⚠️ 我们不是医生，不能诊断…` 这句我认为是全项目最好的文案），但前端**一个字都没读**（`grep goalTemplate/tips/notice/placeholders public/app.js` 全为 0）。张姨点了「帮我看懂检查报告」，输入框里填的还是那行标题 —— **帮助就在文件里，没有送出去。**

另一半是**坏东西送了出去**：`src/llm/gateway.js:111` 的 `没有找到 AI Ping 的 API Key。可以在项目根目录的 .env 里填 AIPING_API_KEY。` 被 `public/app.js:1288` 原样渲染给李姐。

**为什么这一件必须排第 3**：它**同时**解决任务书点名的用户特点 3 和特点 5 ——
- 「看不懂术语」（特点 3）：把 API Key / .env 挡在门外。
- 「最容易在我该说什么这一步放弃」（特点 5）：把 `goalTemplate` + `placeholders` 的现成示例送到输入框里，用户照着改就行，不用从零想。

**这一条是"投入产出比"最高的**：文案和结构**都已经存在**，只是没接线。改的是**读取方式**，不是**写新内容**。

**工作量：中**（模板渲染要动一点结构，错误翻译表是小活）。

---

### 为什么不是「改首页顺序」或「加 10 个场景」

那两条（§C 建议、§D-3）**收益也很大，我列进了 F 的第 6、7 条**。但它们的价值**依赖前 3 件先修好**：
把场景模板提到首屏，用户填好了 —— 然后点「开始」报错。**等于把人骗进门再告诉他门是假的。**
所以：**先让流程通（1、2、3），再优化引导（6、7）**。

## H. 我原本以为有问题、实际体验后发现没问题的地方

**（诚实记录。以下都是我一开始怀疑、走查后确认没问题的。）**

1. **「断网也能打开、没有任何外部请求」—— 我原本以为是吹牛。**
   实测：首页所有资源（`styles.css`、`app.js`、内联 SVG favicon）**全部来自 `127.0.0.1:8899`**，没有一次外部请求。`index.html:11-12` 的注释也说明了 favicon 用内联 SVG 是为了离线。**这个承诺是真的。**

2. **场景模板的文案质量 —— 我原本准备挑一堆术语。**
   实际读下来，`templates/health-prep.json` 的 `⚠️ 我们不是医生，不能诊断。这份东西是帮你听懂医生说啥、少走弯路，最终一定要听医生的。` —— **这是全项目最会说话的一句**，把免责说得像关心。
   `templates/job-application.json` 的 tips：`不用写得很好看，把你干过的事用大白话列出来就行，剩下的交给我们。` —— **完全没有任何术语**，李姐看了会有安全感。
   `templates/life-decision.json` 的 `不要和稀泥，要说实话。` —— 好文案。

3. **演示内容本身（`src/demo/fixtures.js` 的 `ARTIFACT_RISK`）—— 我原本以为演示就是占位符。**
   实际是**真能用的东西**：三条风险，每条都给「合同原文」→「对你不利的地方」→「建议改成（含具体法条式措辞）」，还提醒「一定要加：原有家电清单（品牌+型号+现状照片）」。**这个质量远超"演示"的预期。** 问题只在它和用户问的不匹配（§E-9），内容本身不用动。

4. **`failureState` 的四段式失败界面 —— 我原本以为失败提示都很敷衍。**
   `title: '这一步没做成，但之前做的都留着'` / `next: '不用重头再来。点下面的按钮，团队会从卡住的那一步接着做，前面已经完成的部分不会丢。'`（`public/app.js:1286` `:1289`）
   **"但之前做的都留着""不用重头再来"** —— 这两句精准地回答了普通用户失败时最大的恐惧（白干）。**设计是对的，只是现在用户看不到它**（缺陷 1）。

5. **「不甩脸子给你看」这条自我承诺 —— 我原本当成营销话术。**
   代码里确实做了：`src/pipeline/engine.js:943` 的注释记录了他们**曾经**把质检 `needs_revision` 判为任务失败，后来主动改成**不判失败**（`:988`），理由写在注释里：`质检员很诚实地判了 needs_revision，整个任务因此标记为失败 —— 用户白等 4 分钟。`
   **他们想到了"用户白等"这件事，并且改了。** 这个价值观我认为是真的。

6. **「给谁看」和「语气」两个下拉框 —— 我原本以为多一个输入框就流失一半人。**
   实测：它们**有合理默认值**（`我自己看` / `正常语气`，`public/app.js:216` `:220`），用户**完全可以不管**它们直接点开始。不构成填写负担。**这个设计是对的。**

7. **`#/` 和未知路由的兜底 —— 我原本以为会白屏。**
   实测：未知路由给 `这个页面不存在 / 地址可能拼错了。回首页重新开始就行，不会丢东西。` + `[回首页]`（`public/app.js:1410-1415`）；历史为空给 `还没有任务 / 这里会记下你交出去的每一件事和拿到的成果。第一件事想从哪儿开始？` + `[现在就说一件想做的事]`（`:403-408`）。
   **都有人味，也都有出口。** JS 完全禁用时 `index.html:17-23` 还有 noscript 说明。**这块做得比大多数商业产品好。**

8. **`你只管说想要什么` 这个主标题 —— 我原本觉得"想要什么"太虚。**
   配上输入框的灰字提示 `比如：帮我把这份租房合同看一遍，我怕有坑`，**"虚的标题 + 实时的例子"组合起来是有效的**。李姐 3 秒内能懂（§C）。**标题不用改。**

9. **无障碍（aria-label / `aria-live` / skip-link）—— 我原本以为普通产品不会认真做。**
   `/api/health`、`role="status"` / `aria-live="polite"`（`public/ui.js:677`）、`跳到主要内容` 跳转链接（`public/app.js:142`）、`sr-only` 标签（`:265`）。
   **做得很细。** 唯一的瑕疵是 `aria-label: '虚拟员工流水线'` 用了「流水线」这个工厂词（见 §B #10）。

10. **安全与防注入 —— 我原本准备找拼接 HTML 的漏洞。**
    `public/ui.js:25` 有 `escapeHtml`（转义 6 个字符），`public/app.js:43-46` 明确注释 `用 textContent 建节点，绝不拼 HTML 字符串`，`src/routes/jobs.js:120-136` 的 `sanitizeFilename` 防响应头注入和目录回溯。**态度是认真的。**

## 收尾：一句话给负责人

**这个产品的"心"是对的** —— 失败的提示会说"之前做的都留着"，质检不通过不判失败（怕用户白等），免责声明写得像关心，场景模板不说术语，断网真的能用。
